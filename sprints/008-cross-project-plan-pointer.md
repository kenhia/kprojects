# Sprint 008 — The cross-project-plan pointer, and a drift that wasn't

2026-08-17 · korg proposal 1407 · covers #1406

## Goal

The kprojects slice of the **cross-project planning rollout** (program korg
1405), split out of proposal 1403 when the agent-skills half found what looked
like reconcile work here. Slice 2 (`agent-skills` [PR #21](https://github.com/kenhia/agent-skills/pull/21),
`fcdde6a`) taught the skill trio to check the plan at three chokepoints —
`refill-queue` for direction, `start-sprint` before briefing, `sprint-ship` at
the divergence moment. This slice adds the fourth surface: the managed block
every agent reads, in every repo, whether or not a skill fired.

Three items in #1406: reconcile the template before reapplying, add the
pointer, reapply to korg, kfdc and kfo.

## Decisions

- **Item 1 had no work in it: the template was never stale.** #1406's premise
  was that `harness/instructions.md` at HEAD lacked the "mark each work item
  resolved" line and still carried a hardcoded `uv`/`ruff`/`ty` stanza, so a
  reapply would downgrade three repos. It does not. The shared section of the
  template renders **byte-identical** to the blocks deployed in agent-skills,
  korg, kfdc and kfo, and the stanza has been per-stack since sprint 002.
  Verified by diffing the rendered block against all four deployed copies
  before touching anything.
- **The drift was in the reading, not the template — and #1406 asked for the
  cause, so here it is.** Two clones:

  | clone | HEAD | state |
  |---|---|---|
  | kai `~/src/ai-agents/kprojects` | `84d0765` (2026-08-14) | current |
  | kubs0 `~/src/ai-agents/kprojects` | `e3fe180` (2026-07-28) | `harness/` still at the pre-002 path, hardcoded Python stanza, no mark-resolved line |

  Every symptom #1406 lists is a symptom of `e3fe180` specifically. The
  originating session was on cleo, where kprojects is not checked out at all,
  so it read the template through kaed — and kubs0 is the clone kaed reaches
  by default for `~/src/ai-agents`. It read a July template and compared it
  against an August block.

  This is the drift class program 1405 exists to close, arriving as a
  *finding about the finding*: the stale clone is already known (korg #737,
  and sprint 007 deliberately left it alone so as not to entrench it), but
  "known and left alone" is exactly how it went on to produce a false
  reconcile item, a split proposal and a downgrade scare for three repos. Left
  alone again here — dropping it is k-homelab's call, not this branch's — but
  filed as a follow-up with the evidence attached, which it did not have
  before.
- **The pointer states the applicability test first, then the location, and
  stops.** Nine lines: one grep of `index.md`, the repo location both ways,
  don't-clone-a-second-copy, then the two obligations. The failure mode named
  in proposal 1403's notes is the one being avoided — vague instructions get
  token-taxed in every repo and acted on in none — so an unmapped project pays
  one grep and nothing else, and the block never says "consider the plan".
- **The rule lives in the plan repo; the block carries a pointer.** Same call
  the skill trio made, for the same reason. The location is now duplicated in
  four places (three skills + this block) and that is affordable; the amend
  procedure, the supersede-don't-delete rule and the commit convention stay in
  `cross-project-planning/README.md`, which the block points at rather than
  restates. Four copies of a location drift far less than four copies of a
  procedure — and `test_the_plan_pointer_does_not_restate_the_plan_repos_own_rules`
  pins it, asserting `GP-` and "supersede" are *absent* from the block.
- **Every stack carries it.** Being mapped is a property of the project, not
  of its toolchain, so the pointer goes in the shared section above
  `{{TOOLING}}` and the test is parametrized over all five stacks.
- **It goes in `### Workflow`, before the TDD bullet.** The first three
  Workflow bullets are the korg/klams cluster — where planning knowledge lives
  and how a sprint reports progress. The plan pointer is the fourth answer to
  that same question; TDD is standalone and reads better as the closer.
- **Reapply after the merge, not from this branch.** `kproject-install` builds
  from `git+https://github.com/kenhia/kprojects`, i.e. from **main** — sprint
  007's ordering lesson, and it applies unchanged. Running it from this working
  tree would land a block the PR could still change and buy a second pass.
